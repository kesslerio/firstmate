Pi 1.2.0 and Pi 1.3.0 each armed the real home watcher from this worktree in a marked lab home created by bin/fm-lab-home.sh. The session lock was the driver, a private tmux socket was used, and the model was the offline probe-local provider. The owner check registrar bound waker3, and the armed watcher fired that check once. The driver did not write the wake queue.

On both versions the extension delivered that wake as a user follow-up. A custom triggerTurn whose content exactly equaled that pending wake had no prompt, raised no TypeError, left generation=1 phase=active unchanged, and did not acknowledge the queue. The drain command still printed WAKE_ACK_REQUIRED and the same queue row. Session replacement then showed the wake still pending and undelivered.

The following user boundary carried the same text, advanced the marker to generation=2 phase=active, and cleared the handoff. That consumption did not acknowledge the durable queue; acknowledgement stayed a separate owner action the custom turn never performed. turn_start was recorded for both the custom run and the user boundary. The loaded watch-extension hash matched the worktree file, and the marker pid was the Pi pid.

Lab homes, private sockets, and owned process groups were removed. No lab process remained.
